What the comparison isolates

Component movement: this implements the maintainer's recipe. A content container is cached by record and column, then moved into whichever TD currently displays that logical cell. The vertical scenario isolates the remaining reparenting cost.

Nested headers: compare realistic groups of three with a single group placed only at the right edge. The 2D scenario visits both horizontal edges, exposing viewport expansion without forcing all 40 columns into the DOM.

How the metrics are collected

The renderer uses a WeakMap keyed by the TD and source record. A cache miss performs real DOM work only: it creates a wrapper, native SVG icon, label, and status badge. There is no synthetic CPU loop. Coordinate-aware DOM recycling preserves the rendered state, while stationary positional reuse invalidates it as rows pass through the viewport. The nested-header case groups all 40 columns so the viewport-expansion cost is directly visible in the rendered-column and rendered-cell counters.

The benchmark performs the same vertical round trip at the left edge, scrolls through all 40 columns, repeats the vertical round trip at the right edge, and returns left. It waits for one animation frame after every step. Frame durations come from requestAnimationFrame; long tasks come from the browser Long Tasks API; DOM rebuilds are counted only when a new SVG-rich container is constructed.
